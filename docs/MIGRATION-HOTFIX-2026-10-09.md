# 2026-10-09 启动迁移修复

## 原因与改动

旧版运行事件包含 `runId`。schema 2 → 3 迁移为运行分配新身份时，嵌入事件仍引用旧身份，触发 `package_scope_mismatch`，使启动进入维护状态。失败位置在纯转换的归属校验，早于迁移备份、控制日志与主数据提交。

- 事件引用转换后的父运行身份，保留事件序号、时间、类型、正文与稳定身份。
- 运行的 `evaluationIds` 同步转换，仅保留同数据包内存在的评价，按首次出现顺序去重。
- 历史快照保留显式关联的缓存评价，包括 `runId=null` 与源于先前同目标运行的评价。
- 缓存评价的原始来源运行、缓存键及唯一实体不变；显式列表不作为推断数据归属的证据。
- 继续执行归属校验、迁移前备份、提交日志与中断恢复，不删除用户数据或绕过校验。

## 回归证据

`tests/integration/package-migration.test.mjs` 使用合成简历、目标、岗位与事件。

1. 生产结构事件测试在修复前复现相同 `package_scope_mismatch`，修复后通过。
2. 缓存评价测试在修复前证实运行仍持有旧身份；修复后动态与磁盘快照均保留本包评价，拒绝异包与缺失引用。
3. 基础夹具增加事件 `runId`、`schemaVersion`、`payload` 与 `lastSeq`，让已有失败提交、重复启动及清理重试测试覆盖这一实际结构。
4. 最终迁移专项 **12/12**，重复转换、控制身份与磁盘快照保持稳定。

诊断时对现有数据只进行内存转换检查，不写主数据、控制目录、快照或备份，不发送外部请求。检查通过且原始文件哈希保持不变。真实正文、身份编号及私人路径未进入本报告或提交。
