# Job Radar v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有脚本升级为可长期使用的个人求职工作台，扩大招聘渠道并保留历史与人工记录。

**Architecture:** 沿用一个 Node 进程、ESM、Electron 和 CLI；入口共用应用服务。领域规则无 I/O，文件 repository 管理事务与迁移，来源通过共享请求层接入。按五个子系统交付，每份子计划可独立测试，依赖方向固定。

**Tech Stack:** Node >=20、原生 ES modules/CSS、Node 内置测试运行器、pdfjs-dist、Acorn、Electron；生产不引入数据库或前端框架。

**Spec:** [已批准设计及渠道调整](../specs/2026-10-04-job-radar-v2-design.md)

**Evidence:** [渠道只读核验记录](../../reports/2026-10-05-source-research.md)

## Global Constraints

- Node >=20；生产代码继续使用 ESM；前端采用拆分后的原生 ES modules 与 CSS。
- 只在当前隔离工作副本实现；测试使用独立临时数据目录，禁止访问原项目业务目录。
- 迁移读取旧数据前备份；损坏/过新 schema 不静默变为空库；人工记录独立于采集和评分。
- API Key 不进入历史结果、普通日志、导出或浏览器持久化存储。
- 模型默认最多 20 次 HTTP 请求（含重试与格式修复），每请求最多 4000 输出 tokens。
- 标准覆盖 maxSites=12 / maxRequests=120；广泛覆盖 maxSites=24 / maxRequests=240；两者 maxKeywords=6 / maxPagesPerQuery=2 / maxDetails=20。
- 新增至少 6 个自动采集适配器，覆盖至少 4 类渠道；目录至少 20 所高校（4 种系统）、10 家企业（3 家非互联网行业）、6 个公共/地方/行业公告站点。
- 搜索缺席不是 closed；未知资格不等同 fail；总分表示匹配排序，不表示录用概率。
- 原 start/desktop/CLI 参数与 v1 HTTP 行为保留；共享部署为受口令保护的单工作区。

## Review Focus

1. 两个进程同时改备注/采集岗位，必须保留两次提交；B1 的双进程竞争测试负责。
2. 新渠道把社招或公告当校招具体岗位，必须保留真实 kind/type；C4–C6 的契约测试负责。
3. 用户清空备注、换简历、重跑检索，人工记录不能复原旧值或丢失；B4、D3、E4 测试负责。
4. 取消发生在排队/429 重试/详情/模型时，不能继续新增请求；C1、D2–D4 测试负责。
5. 浏览器断线、应用重启或损坏数据，必须可恢复并如实显示任务状态；B5、D4、E7 测试负责。

## 各阶段共用契约

全部定义在 A1 的 contracts.mjs，以 JSDoc 类型及运行时校验实现；不是迁移到 TypeScript。时间为 ISO 8601 UTC；缺失事实为 null/unknown；原始金额保留 unit/currency。

```text
ProfileRevision { profileId, revision, revisionId, text, profile, overrides,
                  contentHash, parserVersion, createdAt }
ConfirmedProfile { education, major, graduationYear, skills, certificates,
                   projects, internships, cities, explicitFacts }
SearchTarget { targetId, revision, revisionId, profileRevisionId, enabled,
               roles, cityMode, cities, graduationYear, jobTypes,
               degreePolicy, sourceIds, siteIds, coverageMode, budgets, createdAt }
Job { jobId, kind, canonical, sourceRefs, identityAliases, firstSeen, lastSeen,
      targetFirstSeen, lifecycle, lifecycleEvidence, deadlinePassed, duplicateGroupIds }
SourceRecord { sourceId, siteId, sourceRecordId, identityScope, kind, title,
               company, cities, jobType, graduationYear, level, url, applyUrl,
               description, degree, experience, requiredCertificates, deadlineAt,
               publishedAt, salary, evidence, parserVersion }
Observation { observationId, jobId, runId, sourceId, siteId, sourceRecordId,
              observedAt, parserVersion, contentHash, fields, evidence }
Evaluation { evaluationId, jobId, profileRevisionId, targetRevisionId, jdHash,
             ruleVersion, promptVersion, modelFingerprint, qualification,
             score, components, evidence, gaps, completeness, status, recommendation, createdAt }
Application { jobId, status, note, resumeRevisionId, appliedAt, followUpAt, events }
Run { runId, targetSnapshot, status, stage, coverage, counts, usage, issues,
      lastSeq, startedAt, finishedAt, snapshotRef }
RunEvent { schemaVersion:2, runId, seq, type, at, payload }
Coverage { sourceId, siteId, queries, cities, pages, truncated, status,
           startedAt, finishedAt, reason }
Issue { code, sourceId, siteId, message, retryable, evidence }
Site { siteId, providerId, category, name, institutionUrl, origin, tenantId,
       regions, majorFamilies, capabilities, evidenceUrl, verifiedAt, status }
Workspace { schemaVersion:2, revision, profiles, targets, jobs, observations,
            evaluations, applications, runs, sourceHealth, identityAliases,
            duplicateGroups, recoveryRecords, migration, settings }
RunSnapshot { run, profileRevision, jobs, evaluations, events }
```

profiles/targets 为 ID → 不可变 revision 数组；实体集合为 ID → 实体字典。revisionId 使用 `<id>@<positive integer>`；Evaluation.targetRevisionId 对应 SearchTarget.revisionId。Job.canonical 使用 SourceRecord 的事实字段，不包含全局 score；targetFirstSeen 为 targetId→ISODate。Job.lifecycle 是 observed/notRecentlySeen/inaccessible/closed/unknown，lifecycleEvidence 保存证据，deadlinePassed 单独布尔值。salary 为 {min,max,unit,currency,raw}，unit 为 day/month/year/unknown。SourceRecord.sourceRecordId 可为 null，由 identity 决定后备标识。kind 为 job/recruitment_notice/company_campaign；jobType 为 campus/internship/social/unknown。

Workspace.settings 为 {sourceOverrides,customSites,model,budgets}，只存脱敏配置；model 包含 endpoint/model/mode，不含密钥。sourceHealth 以 sourceId/siteId 复合键保存。旧文件迁移标记和恢复记录使用各自结构，不误当实体字典。

ConfirmedProfile 沿用现有画像字段的兼容映射；skills/certificates 保留 evidence/proficiency/是否明确拥有，explicitFacts 区分未写与明确没有。领域规则消费 ProfileRevision.profile，版本/确认文本由应用服务处理，不能将 revision 对象误当技能画像。

Evaluation.status 为 rule/ai/rule_fallback/legacy/error，recommendation 为 high/maybe/insufficient/not_eligible；不把模型执行状态与推荐结论混用。completeness 为 {status,knownFields,missingFields}，status 为 sufficient/partial/insufficient。缺 JD 的 recommendation 为 insufficient，明确硬门槛 fail 为 not_eligible，不能仅因总分高变为 high。

                onBatch:(records:SourceRecord[])=>Promise<void>, clock, logger }

  -> Promise<{status:number,headers:Record<string,string>,text:string,url:string}>

Source.collect 的 onBatch 是事实增量；返回 records 是本次汇总，D3 按 observation 身份幂等写入，不能两次计数。probe 状态为 ready/empty/restricted/unavailable/parse_error；empty 不计为接入通过。所有网络错误在来源边界转为 Issue，调用方取消仍传播 AbortError。Repository 不向服务返回可被外部修改的缓存对象。

## 配套决策

- A3 引入固定版本 Acorn；执行时查当前官方包并锁定，不以远程源码运行代替解析。
- A1 建立 `tools/test-v2.mjs` 自动发现 tests 下的 *.test.mjs，支持 --file、--group、--list；默认 preload 零网络 guard。旧套件接入同一隔离目录与 guard。
- 测试 helper 的 job/profile/target 创建合成实体；tempRepository(t) 注册清理。fixtures 不携带真实简历、Key 或受限网页。任务断言中的 named fixture/helper 在该测试文件内定义，以本任务 Interfaces 调用真实模块；不把这些测试名称误当新增生产接口。
- C6 的实时来源验证是交付 gate，报告实际结果；站点临时失效保留记录并继续同类替代，不能删测试或降级统计凑数。
- 前端行为验证使用浏览器真实操作，自动化测试通过可控服务/测试 DOM 完成关键状态，开发依赖按验证需要选择；产品保持原生模块。
- 内部旧函数迁为 async 时同步修改其源码调用方与测试；外部 CLI 参数、HTTP 请求/响应和桌面入口兼容由 D6/E6 负责。
