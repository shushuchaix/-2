# 根据运行日志修复更新失败

## 证据与原因

只读查看桌面数据目录的诊断记录及任务元数据，没有写入真实求职数据，没有重新执行用户的完整来源更新。

2026-10-06 12:13 至 12:20（香港时间）的一次更新，已经规范化并去重 140 条记录。最终失败的日志显示 `EPERM` / `rename` / `atomic.rename` / `workspace.v2.json`，位于详情阶段保存任务事件。更早的同次更新也出现一次相同文件替换错误，随后仍有成功写入。这证明文件替换失败是间歇性的；日志不能识别当时占用文件的具体程序。

Windows 的已打开目标文件需要允许适当共享才能被替换，参见 [Microsoft 文件移动与替换说明](https://learn.microsoft.com/en-us/windows/win32/fileio/moving-and-replacing-files)。本次另用临时合成文件和隐藏的 PowerShell 文件句柄复现共享锁拒绝替换，验证持有者释放后恢复保存。

来源日志同时显示：14 个 91job 高校站点返回 HTTP 504，每站约 27–29 秒；腾讯返回 `Tencent Posts missing`；NCSS 一次详情抽取失败。两个普通操作错误对应“删除已被引用的简历版本”，引用保护本身正常，原反馈是英文且返回 400。

## 修改

- Windows 文件替换遇到 `EPERM`、`EACCES`、`EBUSY` 时，等待 25/50/100/200/400/800 毫秒后重试，最多六次。沿用已经写入并同步的临时文件，不删除旧文件，不重复业务事务。持续失败保留原始异常、失败阶段及重试次数。
- 工作区与任务快照替换恢复后记录 `storage.recovered`，包含已知文件名、错误代码、次数和累计等待时间；设置页全部日志可查看。诊断日志失败不影响已完成的保存。
- 保存任务状态或来源进度的持续存储错误会终止任务并标明工作区写入失败，保留原始错误代码；不会再归为招聘网站故障继续运行。已入库的岗位仍保留。
- 腾讯官方接口的 `Code:200, Count:0, Posts:null` 当作正常空结果；有岗位却缺少数组等格式异常仍报错。
- NCSS 的 `pagenation.count` 是岗位总数，`total` 是总页数；按岗位总数判断是否有下一页，继续遵守每查询至多两页。正文首选区域过短时使用已有备用正文区域，并记录实际命中的选择器。
- 91job 列表及详情请求最长 12 秒，不再自动对同次网关失败连试三次；其他来源沿用默认重试策略。请求仍计入原有预算且可取消，没有新增批量请求或替代接口。
- 删除已引用简历返回中文说明、409、`profile_revision_referenced` 与字段信息；目标、任务、投递记录三类引用继续阻止删除，未引用版本可正常删除。

## 来源核查范围

共完成八次公开只读 HTTP：腾讯两次，91job 同一代表站点的原 API 与公开主页各一次，NCSS 四次（列表及两类详情）。腾讯零结果响应和 NCSS 分页字段已获得官方接口证据。91job API 和主页均返回 504，未取得前端路由证据，因此保留原接口。

NCSS 两个真实详情样本当前均可抽取正文；另用合成页面复现“首选区域只有短提示，备用区域已有完整正文仍被拒绝”的缺陷。不能将该缺陷断言为用户当时那条详情失败的确定原因。

- Node 20.20.2 完整离线门槛（含实际包检查）：18 套件通过，v2 236/236，0 失败、0 取消，6 项外部联网套件明确跳过。结果：`.cache/log-guided-release.log`。
- 实际 Windows 文件共享锁恢复测试通过；同一事务回调只执行一次、持续失败保留旧文件、临时文件清理、不可重试错误与日志故障隔离均通过。
- Windows 便携包重建，ASAR 1649 文件、0 项问题；整个便携目录 362.1 MB。
- 重建 EXE 隐藏隔离自检：27/27，退出码 0，含真实渲染器字段反馈、日志查看及导出。结果：`.cache/log-guided-desktop-20261006/data/desktop-self-test.json`。
- 独立只读增量审查涵盖数据保留、重试边界、取消与预算、异常传播及日志脱敏；未发现本次新增的 P1/P2 问题。

## 仍有的限制

91job 的外部 504 仍存在，本次缩短失败等待，不能保证外部服务恢复。文件持续占用、目录权限或磁盘故障超过重试范围时仍会明确报错，需依据新版日志继续判断。未对真实个人目标、全部高校或模型凭据进行验收。
