# 招聘更新故障诊断与本地日志

日期：2026-10-06，Asia/Hong_Kong。

## 用户问题及调查

用户在工作台更新招聘来源，运行一段时间后显示失败。只读检查本机最近两次任务的状态、计数和事件，两次均已采集记录，随后出现 `workspace_write_failed`。没有读取或输出简历、密钥、备注及岗位正文，没有写入用户工作区。

旧实现的入库处理同时包住岗位校验、身份解析、进度更新和事件保存；任何异常都被重命名为 `workspace_write_failed`，原始错误代码丢失。用合成记录缺标题复现：纯内存校验错误也被标成存储失败。因此，旧记录不能证明实际发生了磁盘权限问题，也不能还原这两次失败的原始异常。

另已复现 91job（岗位与公告）、SmartRecruiters、Greenhouse 的详情响应缺字段时，会将列表已有的标题、链接或其他事实覆盖为空，可能导致后续校验失败。本次修复这个已证实的程序缺陷；尚不能确认它就是用户此前两次失败的原因。

## 改动

- 工作台提供按当前任务查看、刷新和导出日志；设置页可查看全部最近日志。读取失败保留列表，切换任务忽略过期返回，纯文本显示。
- 本地 `logs/application.log` 与 `application.previous.log` 各最多 2 MiB；内存最多 500 条，查看／导出最多 200 条。文件写入或读取失败会提示暂用内存，关闭前可导出；日志独立于工作区及业务备份。
- 只保存白名单诊断字段：编号、时间、操作、阶段、来源／站点／任务、耗时、错误类型及代码、明确 HTTP 状态、已知安全摘要和相对代码位置。未记录请求正文、headers、简历、备注、Key、密码、网页正文或私人路径；读回日志时再次检查字段。
- 在适配器内部捕获点、单源检查、采集、详情、岗位入库、进度、事件、快照及 HTTP 失败时留日志；把编号返回到错误提示及任务问题中。内部捕获的 HTTP 503／403 也保留状态和编号。
- 保留原始错误代码，区分岗位记录处理、进度和存储失败；致命入库错误继续向外传播。原子写入标记失败步骤，清理错误不再覆盖主要异常。
- 三个来源的详情缺失字段保留已有事实及证据，有效新事实仍可更新，身份校验不放宽。
- 桌面菜单增加「打开运行日志目录」。启动失败提示日志编号、检查权限和空间，保留数据目录。
