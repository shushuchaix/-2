# 简历岗位雷达 v2 · 个人求职工作台

把简历、招聘证据、检索目标和投递进度保存在同一工作区。面向个人长期使用，Web、Windows 桌面和 CLI 共用应用服务。

新增可恢复分批采集、NCSS/官方招聘扩源、公众号与微博正文、专用登录窗口、招聘附件OCR及证据核验。操作见[扩源使用说明](docs/source-expansion-usage.md)，实际线上限制与发行验证见[本次验收报告](docs/reports/2026-10-09-source-expansion-validation.md)。

## 日常流程

1. 在「简历管理」粘贴文本或上传 PDF / DOCX / TXT / MD，查看提取警告，校正事实后为简历版本命名并保存。
2. 在「求职目标」新建目标版本，选一份简历，填写岗位方向、城市、届别、类型、来源和预算。保存时复制完整简历；以后删除原简历不会影响这个目标。
3. 顶部选择一个目标版本，在「工作台」更新招聘来源。没有模型密钥时使用规则模式；部分来源失败仍保留已取得的记录与原因。
4. 在「岗位库」查看所选版本的岗位、公告、公司招聘窗口及资格证据、匹配分项、来源日期。匹配分用于排序。
5. 在「投递进度」记录状态、备注、这个目标自己的简历和跟进日期；在「日志」排查更新错误，在「设置」导出业务备份。

侧栏分为三组：日常（工作台、岗位库、投递进度），准备（简历管理、求职目标、招聘来源），管理（日志、回收站、设置）。页面地址保存目标范围与筛选；刷新、返回或快速切换版本时，旧请求与事件不会覆盖当前版本。关闭浏览器不会取消后台更新；关闭桌面程序会停止并保存运行状态，下次启动显示中断记录。

## 版本管理与全版本清理

- 简历和目标分别要求版本名称（1–60 字符）。全角、大小写和多余空白统一比较；同类型的同名仅保存一份，包括停用、回收站和清理待完成的版本。不同名称可同时保留，重命名、启停不会另建版本。完全永久清理后才释放名称，内部编号不会重用。
- 每个目标有自己的简历副本、岗位事实、观察、评价、检索记录、投递及事件。A 中修改投递或清理重复岗位不会改变 B；即使公开岗位相同，两份个人记录也各自保留。「全部目标」供汇总查看，修改前须切到具体版本。
- 「停用」保留版本和记录，但停止新的更新。岗位库可组合筛选记录类型、推荐结果、资格、投递和重复情况，未评价岗位也属于采集它的版本。
- 「清理所有版本重复岗位」先逐版本生成预览，再分别归并确定重复项；不同版本之间不合并。有效期内回收包只能由此维护入口参与去重，已到期或清理待完成的包不读取正文。疑似重复或独立人工记录冲突需要人工判断，不自动删除。预览后数据变化会拒绝旧预览并要求重新生成。
- 去重前自动备份业务数据，再原子归并；旧岗位编号在所属版本内可继续解析。旧数据无法确定唯一所属版本时放入「待归属旧数据」，可在设置页查看、预览并移动到一个明确目标，不能同时归给多个目标。
- 设置页提供工作区、历史、备份、缓存和日志的打开／复制入口。`workspace.v2.json` 保存主业务，`runs-v2/` 保存运行快照，`backups/` 保存应用管理的业务备份，`control/` 保存稳定身份、转移和删除控制，`cache/` 可重建，`logs/` 保存安全诊断。不要单独移动或删除 `control/`。

## 回收站与三天保留

- 在简历或目标管理中「移入回收站」，会整包隐藏该版本及其子记录。活动更新需先取消并等写入结束。源简历包与目标中的副本独立，删除源简历不会级联删除已经保存的目标。
- 回收站显示类型、归档时间、永久删除时间和记录数量。未到期可以查看、恢复；恢复沿用原编号、名称及启停状态。归档后满 **72 小时**不可再查看正文或恢复。
- 「永久删除」处理所选整包；「清空整个回收站」处理全部回收包，当前搜索或分类不会缩小清空范围。确认前显示完整计数，取消不会删除，过期预览要求刷新。
- 程序启动先补清到期内容，运行中每五分钟检查。程序关闭期间不会运行清理；再次启动补清，保留期限不会延长。存储或文件占用导致清理未完成时显示匿名任务编号、错误编号和重试入口；该版本不恢复、不泄露正文，也不提前释放名称。
- 永久清理包括主库、运行文件、上一版及本软件管理的旧存储和备份。不会生成一个长期保留完整待删内容的“删除前备份”。用户另外保存的导出备份无法由软件远程擦除，但在本机恢复时会验证原始完整性并过滤已永久删除的记录；恢复旧备份也不会复活到期版本、改写本机未到期归档或重置删除控制。

操作完成后会出现可关闭的可见通知。清理与升级只备份业务数据，不含密钥；日志继续不记录简历、求职词、正文或私人路径。本次说明和证据见 [UI 与桌面验收](docs/UI-ACCEPTANCE.md)，历史说明见 [版本与去重交付报告](docs/reports/2026-10-08-workspace-version-and-dedup.md)。

简历PDF导入需要可提取的文字层。图片型/扫描件简历PDF会明确提示没有文字；简历导入暂不提供OCR。招聘附件与公开海报支持本地OCR。简历可上传文字版PDF、DOCX或TXT，或先清除已选文件再粘贴正文。

## 填写检查与错误反馈

各表单提供必填／可空和格式说明。离开填写项时检查格式；提交会检查全部内容、列出错误并定位到第一项。修改正确后提示自动清除。保存失败会保留输入并显示未保存状态，等待保存时禁止重复提交。

检查覆盖简历文件和正文、画像事实、检索目标、工作台、岗位筛选、投递记录、岗位关联、招聘导入、来源和站点设置、模型和 Key、备份恢复／导出及登录。后端在写入前检查类型、日期、长度和引用；网络、权限和存储失败提供独立反馈。

- 简历文件支持非空 TXT／MD／DOCX／PDF，最多 20 MB；正文 30–60,000 字符。文件与粘贴正文同时存在时优先读取文件。
- 未知画像事实可留空；年份填四位 1900–2100。指定城市时需填写城市，岗位方向与招聘类型至少选一项。
- 投递和跟进日期检查真实日历日期，可记录过去或未来日期；备注最多 20,000 字符，清空后保存可删除原内容。
- Key 可空，填写时最多 512 字符且不含空白；兼容服务商不限制固定前缀。规则模式无需发送 Key。
- 恢复使用本软件导出的完整 JSON 工作区备份，最多 38 MiB；岗位导出文件不能作为工作区备份恢复。

## 更新失败时查看日志

在「日志」页选择业务记录或系统诊断，可从工作台的任务入口直接跳转。查看所选版本任务的来源、失败步骤、HTTP 状态和错误编号，按级别、分类和完整编号筛选，刷新或导出。具体目标只显示它自己的业务诊断；全部目标提供汇总及公共系统诊断。界面最多显示最近 200 条，导出覆盖当前筛选下仍保留的全部匹配日志。旧任务不能补出当时未采集的诊断字段。

日志用任务、请求、启动会话和错误编号关联前后步骤；包含阶段计数、请求排队／DNS／传输耗时、重试、预算用量、解析结构检查和运行环境版本。只保存白名单元数据，不记录简历、个人画像、求职关键词、网页正文、模型输入输出、原始 URL／查询参数、请求头、密码、Key、私人路径或原始控制台内容。字段与限制见 [全面日志升级说明](docs/reports/2026-10-07-comprehensive-diagnostics.md)。

桌面菜单「文件 → 打开运行日志目录」可打开本地 `logs/`。日志最多保留两个 4 MiB 文件；当前进程的内存最多保留 1,000 条。轮转会覆盖较早历史，面板和导出会显示当前保留范围、损坏记录和截断提示。日志文件无法写入或读取时会明确提示并暂存在内存，请在关闭软件前导出。日志独立于求职数据及业务备份。

Windows 保存遇到短暂的 `EPERM`、`EACCES` 或 `EBUSY` 时，软件会在约 1.6 秒的总等待内最多重试六次文件替换；成功后设置页全部日志显示「自动重试后已保存」。持续失败仍会报错并保留原有有效数据。91job 网关失败每次请求不再自动连试三次，单次请求最长 12 秒；站点仍不可用时，日志保留 HTTP 状态，其他来源继续更新。

## 启动

要求 Node.js 20 或更高版本。

```powershell
npm ci --ignore-scripts
npm run build:ui
npm start
```

访问终端显示的本机地址。也可使用 `start.cmd`。首次使用不需要模型密钥。

Windows 便携版位于 `dist/简历岗位雷达-win32-x64/简历岗位雷达.exe`，整个目录一起移动。源码开发及打包：

```powershell
node tools/fetch-electron.mjs
npm run build:ui
npm run desktop
npm run dist:desktop
npm run verify:package
```

下载器核验 Electron 官方 SHA-256。桌面 renderer 保持 sandbox、contextIsolation 和禁止 Node 集成。设置页可通过系统加密保存、清除模型密钥；系统加密不可用时明确拒绝保存。

## 数据与升级

- Web / CLI 默认使用项目 `data/`；`RJR_DATA_DIR` 可指定另一可写目录。
- 桌面使用用户可写目录，可从「文件 → 打开数据目录」查看。
- `workspace.v2.json` 文件名保持兼容，内部格式升级到 schema3；`runs-v2/` 保存有独立身份和归属的运行快照。
- v1/v2 首次启动先备份、准备稳定身份、迁移到独立包，再消费旧业务入口。中断可重试；旧归档只获得一次至少 72 小时的迁移宽限。损坏文件或不支持的格式报告错误，不静默清空。
- 已初始化的 `control/` 缺失或损坏时停止业务和恢复，仅保留健康检查及安全日志用于诊断。不要用旧版本软件打开已升级目录。
- 设置页的业务备份包含个人资料，应按个人文件保存。密钥、会话和系统加密文件独立于业务备份。

本次九页界面、独立版本与回收站验收见 [UI 与桌面验收](docs/UI-ACCEPTANCE.md)；历史升级说明见 [v2 升级指南](docs/v2-upgrade-guide.md)。

## 招聘渠道

本版保留八类旧来源适配器，并增加国家平台、高校、企业公开职位接口、研究机构公告和社交线索通道。

2026-10-05 实际探针取得 **6 个新增直连适配器、4 类渠道、30 个有效站点**：20 个 91job 高校、NCSS、腾讯、博世、Canonical 和 6 个研究机构公告站。只表示本次能够读到 ID、标题、URL 与要求正文，未来可能变化；候选目录与已接通站点分别显示。

目录包含 30 所高校 / 4 类就业系统、11 家企业、6 个公共公告站点及平台目录。旧来源或候选目录不能凭数量认定可用；在「招聘来源」检查单个来源，查看实际状态。来源可能返回可用、空结果、访问受限、不可用或解析错误。详见 [来源验收报告](docs/reports/2026-10-05-source-readiness.md)。

### 微信公众号、微博、抖音

可以成为招聘线索来源。已配置搜索 API 时发现公开 URL；在「导入招聘线索」保存账号、链接和用户提供的正文，按公告展示。正文足够且模型可用时可抽取有原文支持的具体岗位，并保留原公告。

本次没有验证成功的三平台直接自动采集通道。需要登录、平台权限或授权接口的内容保留明确状态；搜索摘要和人工导入不计入直连来源验收。Scrapling 用于公开页面研究，已禁止路径没有正文采集。依据与限制见 [社交来源研究](docs/reports/2026-10-05-social-sources.md)。

## 模型、搜索和预算

规则模式无需密钥。模型辅助提供分项解释，模型输出必须引用真实原文；资格硬门槛失败不能被模型高分覆盖。缺失事实保持待核实。模型质量尚未做带真实密钥的人工评测，不能据此承诺精排效果。

Web 临时模型密钥只用于本次任务；不写浏览器存储、历史结果或导出。服务端可用 `DEEPSEEK_API_KEY` 配置密钥；配置文件与环境变量须自行妥善保存。搜索 API 可配置 Tavily、博查或 Serper，具体字段见 `config.example.json`。

| 预算                                 | 标准 | 广泛 |
| ------------------------------------ | ---: | ---: |
| 站点                                 |   12 |   24 |
| 来源请求（含重试、重定向与安全解析） |  120 |  240 |
| 关键词                               |    6 |    6 |
| 每查询页数                           |    2 |    2 |
| 详情                                 |   20 |   20 |

官方 DeepSeek V4.1 的 API 模型名是 `deepseek-flash`，地址为 `https://api.deepseek.com`。在「设置」填写并保存「每任务模型费用上限（元）」即可启用人民币预算，允许 0–10 元、最多两位小数；0 不发送模型请求。目标版本也可设置费用上限，检索和重评都遵守目标与全局配置中较小的上限。该模式共享同一任务账本，重试与格式修复都计费，原 20 次限制改为 1000 次辅助保护。每次最多 4000 输出 tokens。

界面与日志显示「费用上界」，按已核实的高峰价和输入缓存未命中价计算，不等同于服务商账单。发送前预留完整上下文的最高费用；返回可信 token 用量后释放余量，网络失败或用量缺失时保留预留。因此剩余预算不足以预留下一次调用时会停止，即使显示金额尚未达到上限。人民币模式只适用于已核实价格的官方 `deepseek-flash`；兼容服务商或清空费用上限后沿用最多 20 次 HTTP 尝试的旧模式，不显示虚构费用。

岗位匹配只发送经过白名单筛选的学历、专业、年份、技能、证书等职业事实及公开岗位输入，去除姓名、学校、联系方式、原始简历和经历叙述；公共招聘公告提取不发送候选人画像。AI 简历解析是独立操作，选择该操作仍会把待解析正文发送到配置的模型。实际运行与验证说明见 [V4.1 与人民币预算验收](docs/reports/2026-10-08-v41-money-and-live-run.md)。

## CLI 与旧参数

```powershell
node src/cli.mjs --resume tools/sample-resume.txt --no-llm --format json
node src/cli.mjs tools/sample-resume.txt --cities "北京，上海" --keywords "Java，SQL" --year 2027 --no-intern --format csv --out results.csv
node src/cli.mjs targets list
node src/cli.mjs runs start --target TARGET_ID --rules
node src/cli.mjs runs show RUN_ID
node src/cli.mjs applications set JOB_ID --target TARGET_ID --status applied --note "三天后跟进"
node src/cli.mjs sources probe ncss --site ncss
```

保留 `--resume` / 位置文件、`--text`、`--cities`、`--keywords`、`--year`、`--no-intern`、`--all-years`、`--format`、`--out`、`--no-llm`、`--top`。无 `--out` 时结果输出 stdout，日志写 stderr。旧 CLI／v1 HTTP 个人业务只有能够验证唯一版本时才转换；跨版本歧义明确报错，不读取已消费的旧文件。

## 分享与部署

[部署指南](deploy/部署指南.md) 支持 Docker / Node + HTTPS。公网启动需要口令保护，流式反代需同时覆盖 v1 与 v2 事件路径。

**当前是单共享工作区。所有登录者看到同一份简历和投递记录，没有多人资料隔离。** 分享给他人试用时应使用独立 `RJR_DATA_DIR` 和合成资料；个人真实工作区建议在本机运行。
