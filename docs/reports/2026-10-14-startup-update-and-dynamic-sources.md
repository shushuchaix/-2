# 启动岗位更新与动态来源续验

日期：2026-10-14。本报告记录 10 月 13 日至 14 日的实施与验收。启动更新功能已完成；招聘扩源整体任务仍有缺口。

机器结果见[验收数据](2026-10-14-startup-update-and-dynamic-sources.json)。原 47 个模板缺口的逐项诊断见[上一批来源证据](2026-10-13-official-template-followup120-gaps.json)，其中部分采样时间较早，不能当作今天重新核验全部机构的结果。

## 已实现的使用行为

- 每次打开软件，为选中的启用目标更新一次；只有一个启用目标且未选择时自动选中，多目标未选择时提示选择。
- 启动更新使用本地规则匹配。招聘来源页新增“手动更新岗位”，工作台保留“更新岗位”和模型选项。
- “刷新来源”读取目录及探针状态；“手动更新岗位”实际执行采集。界面显示真实活动进度、新增数量和错误反馈。
- 自动与手动共享已有预算、版本归属、去重和日志。导航、React 重放及同客户端重新挂载不会重复启动；切换版本不会把迟到结果归入新版本。
- 主动暂停、取消、登录限制、重新规划及额度耗尽均显示处理提示，不自动继续这些受阻活动。

## 方法与修复

按批准设计先编写失败用例，再实现应用级启动协调与后端自动续采守卫。后端在规划结束后的事务中再次检查主动暂停，自动续采明确采用 rules 模式，避免继承上次的模型评价模式。

一次独立最终审阅发现 4 项重要问题，均已处理：

| 问题 | 修复与证据 |
| --- | --- |
| 返回工作台时缓存的启动结果覆盖较新的手动任务 | 优先恢复当前活动的运行任务，每个启动结果只消费一次；回归先复现重新连接旧任务，修复后启动界面 19/19 通过。 |
| 一个 DNS 查询失败后另一查询仍在途，窗口退出未等待 | 查询失败取消并等待另一地址族；窗口退出取消自有解析器并排空。DNS 与浏览器专项 37/37 通过，所有 DNS 请求继续由原活动先预约再结算。 |
| 原生验收直接读取原始根记录中不存在的费用属性 | 改为读取 collectionService 的正式费用投影；三个缩放的 EXE 均实际通过零模型费用断言。 |
| 持续追加第 21 份授权后读取器拒绝整链 | 按请求上限统一读取和追加边界，越界在活动额度写入前拒绝；两个失败用例修复后授权链 18/18 通过。此修复属于本地验收工具。 |

首次 EXE 场景的启动和手动更新已经通过，但再次导航到相同 URL 没有建立预期的新启动场景。验收改为明确重新加载应用，再核验只创建一次新活动；完整验证通过，没有删除失败断言。

## 来源实测

### 浙江机场：分页、公告日期与完整正文

从当前官方 HTML 的实际 OPTIONS 配置确认原生分页，使用静态 AST 核对栏目、页大小、总数和接口地址。排除模板脚本及假配置，限制游标边界，并核对详情 ID 与可见标题。未执行网站脚本，也未猜测分页参数。

当前 7 页取得 64 份招聘公告，补齐 3 份正文；这些记录仍保持整份公告身份。实际已见公告存在明确过期截止日期，且附件可能指向 2024 年旧岗位表，不能据此认定为新的在招岗位。原版本中用真实简历进行本地规则验证，当前有效推荐为 0。

最终 CacheOnly 重放读取 10 份缓存，没有新增公网请求、接收字节或模型调用。既有附件富化逻辑仍保守预约了 3 个附件额度，未取得新附件内容；本报告没有把这一过程描述为所有用量均为零。

### 字节校招：正常匿名页面仍未取得岗位列表

匿名读取曾遇到 Fake-IP 系统 DNS、旧静态资源哈希及官网明确引用的静态 SDK 受阻。本批修复受控窗口的活动预算 DNS 回退；重新读取当前 HTML 后采用实际资源路径。静态 SDK 仅允许当前官网引用的精确 GET，验证码响应和认证接口继续拒绝。未合成签名、复制日常登录信息或构造任意 POST。

最后一次复查记录 37 次页面请求事件，未再记录资源失败，但在 45 秒页面读取上限内仍没有加载完成，也没有观察到原生岗位列表请求。此次保守使用 21 次请求上界、322495 字节，取得岗位为 0。去除已知资源拦截没有证明剩余超时的根因已经解决，来源继续未验证。诊断程序退出码 0 只说明执行及资源清理结束，不表示招聘采集成功。
