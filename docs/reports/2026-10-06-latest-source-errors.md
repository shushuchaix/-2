## 根因与修改

### NCSS 原站正文不足

只读请求日志关联的 [公开岗位页面](https://www.ncss.cn/student/jobs/RFWJ2hwaPKxpPohztBe5rk/detail.html)，返回 HTTP 200。两个既有正文容器都有结构，但都仅为 9 字岗位标题，没有职责正文、图片或附件；岗位类型与链接正确。

适配器现在区分两种情况：

- 容器存在但正文为空、过短或只有岗位标题：`detail_insufficient`，不能作为完整要求，不自动重试。
- 预期正文结构缺失：仍为 `parse_error`，保留真实解析错误。

有效的备用正文继续采集，保留原有岗位事实、身份与链接。应用层显示“原网站未提供完整岗位要求，已保留列表信息”，日志记为警告；存储与网络错误仍按错误记录。没有补造岗位职责。

### 91job 504 与界面反馈

通过现有安全请求客户端只读核查常州大学公开首页、首页引用的官方应用脚本以及列表接口，确认原 API 路径。公开列表的空查询返回 HTTP 200、20 条。

用户允许在保护个人信息的前提下复查后，先在本地确认原查询只有通用行业词，再以白名单校验限制输入，仅复查常州大学的一页公开岗位；同样返回 HTTP 200、20 条、约 2.4 秒。没有发送姓名、简历、联系方式、个人凭据，也没有写入真实工作区。

这说明代表站点在复查时恢复；不能据此断言其他三个站点当前正常或全部 504 已根治。保留既有请求上限和来源退避。

界面已复现的缺陷包括：`unavailable` 中的 `ai` 子串被误当成模型错误；终态仍提示“任务在服务端运行”；未显示已保存记录与候选数量；来源汇总按静态目录状态统计，可能与最新健康状态冲突。本次修复这些具体反馈。
