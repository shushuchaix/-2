# 现代求职工作台界面设计

日期：2026-10-10
状态：**待用户审阅，仅书面设计，尚未实施本次界面升级。**
范围：独立完成用户的新界面要求；已批准的来源效能与 Boss 九项实施计划继续执行，无需再次批准既有计划。
依据：完整读取 `ui/src` 的 74 个源文件、5 个配置文件及既有设计，结合 shadcn、UI UX Pro Max 与四张旧 EXE 自测截图。截图用于辅助审查，不代表新版实时验收。

## 1. 目标与边界

让用户首先看见当前版本、可靠的岗位证据、采集进展与可执行的下一步；长篇中文正文易读，科技感由布局、色彩和状态表达形成。
保留已有九页、版本隔离、同名唯一、逐版本去重和整包回收规则；本设计不改变服务端归属、推荐判定、预算账本及删除契约。
目标保存的简历副本独立存在；回收资料库原简历不影响目标副本。目标回收时，其岗位、评价、检索与投递一起回收、恢复或永久删除。
回收站保留 72 小时；应用运行时定期清理，应用关闭期间不会持续执行，下一次启动处理已到期内容。已到期正文不可再查看或恢复。

## 3. 视觉变量与排版

沿用真正的 shadcn Base UI 组件与语义 CSS 变量，导航独立使用 sidebar 变量，避免把导航颜色继续映射到白色卡片。官方 Sidebar 支持独立主题变量与可组合结构。[shadcn Sidebar](https://ui.shadcn.com/docs/components/base/sidebar)

| Token | 值 | 用途 |
| --- | --- | --- |
| `--sidebar` / `--sidebar-foreground` | `#0B1427` / `#DCEAF5` | 深蓝导航与文字，对比度约 14.98:1 |
| `--sidebar-accent` / `--sidebar-accent-foreground` | `#13263D` / `#7DD3FC` | 当前导航底色与文字，并配左侧细线和当前页标记 |
| `--sidebar-primary` / `--sidebar-primary-foreground` | `#7DD3FC` / `#082F49` | 导航中的突出操作 |
| `--background` / `--card` | `#F4F7FB` / `#FFFFFF` | 阅读区底色与内容表面 |
| `--foreground` / `--muted-foreground` | `#102136` / `#53657A` | 白色表面正文与辅助文字，约 16.24:1 / 5.98:1 |
| `--primary` / `--primary-foreground` | `#0369A1` / `#FFFFFF` | 主操作，对比度约 5.93:1 |
| `--accent` / `--accent-foreground` | `#38BDF8` / `#082F49` | 局部强调背景与其文字，对比度约 6.48:1；青色不作白底正文颜色 |
| `--border` / `--ring` | `#D8E2ED` / `#0369A1` | 分隔与键盘焦点，焦点 2px、外偏移 3px |
| 成功文字 / 表面 | `#166534` / `#F0FDF4` | 有效证据、已完成操作 |
| 警告文字 / 表面 | `#92400E` / `#FFFBEB` | 待核验、预算接近上限、需要用户处理 |
| 错误文字 / 表面 | `#B91C1C` / `#FEF2F2` | 失败或不满足；所有状态同时显示文字或图标 |

字体使用本地 system-ui、Microsoft YaHei、PingFang SC；不下载字体，不强行采用仅适合英文的技能字体组合。
页标题 28px、区标题 18px、正文 16px、辅助文字 13–14px、主要统计 32px；数值使用等宽数字，技术 ID 只在详情中使用等宽字体。
间距按 4/8px 阶梯，区块间 24–32px、卡片内 16–24px；圆角 8–12px，边界主要由分隔线与间距表达，阴影限浮层。
视觉效果限页头局部淡网格、细线和轻微渐变；不在正文后铺发光纹理，不用巨大装饰占用岗位空间。装饰设为辅助技术不可见。
状态不能仅靠颜色区分；例如“待核验”必须有文字及缺失项。[WCAG 色彩使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

## 4. 布局与版本上下文

桌面采用 224px 深蓝导航、统一页头、浅色内容区；页头固定位置显示当前目标名称、版本状态、切换入口及当前版本任务状态。
导航三组九页：日常求职（工作台、岗位库、投递进度）；求职准备（简历管理、求职目标、招聘来源）；系统管理（运行日志、回收站、设置）。
用户自定义名称为主要标识，技术 ID 收入详情；所有版本视图与单版本视图显著区分。切换版本保留现有准确的路由归属规则。
未选择版本时给出“选择目标”操作；所有版本汇总为只读时说明具体限制，禁止用空白按钮或无解释禁用状态代替。
内容区上限 1440px，主要阅读列宽约 680–760px，约 42–48 个中文字符；表格使用剩余空间，详情不挤压主列表到难以阅读。
版本切换后立即显示新归属与加载状态，不展示上一版本的岗位或会话；切换失败明确说明仍处于哪个版本。

## 5. 工作台：一个状态、一条行动路径

首行显示目标摘要和“开始检索 / 继续 / 暂停 / 取消”适用操作；紧接一张统一活动卡，负责根任务状态、当前阶段、进展与错误。
根任务决定运行、暂停、取消、完成等活动状态；子批次仅补充当前阶段。旧批次失败或取消不会覆盖新批次运行状态。
新批次启动后清除旧批次结果提示；完成结果进入历史摘要。完成提示区分正常完成、预算耗尽、部分成功、失败及用户取消。
暂停时显示可继续的原因与剩余额度；平台人工验证只影响其来源，不把所有正常来源显示为失败。
进度展示已检查来源、已保存岗位、证据完整岗位及成本；请求上限与高级计数折叠，保留用户查看诊断的入口。
四类证据指标分别呈现，不绘制未经数据证明的包含关系漏斗；不生成虚假增长曲线、动画数字或“覆盖率”估计。
每 100 次请求新增有效且不重复岗位明确分子和已知请求分母；未知请求单列上界，不能混为精确效能指标。
模型累计上限沿用 10 元及根任务账本；暂停、恢复、换批次不会重置。0 元明确表示不调用模型，规则评价仍可运行。

## 6. 岗位库：证据先于评价

列表默认列：岗位与企业、城市、资格结论、正文/在招/入口证据、投递状态、更新日期；分数作为辅助排序信息，保留过滤与分页。
“证据不足”应附一项主要原因，例如“学历条件未知”“截止日期待核验”；资格不满足与信息未知使用不同文字，避免都叫不匹配。
详情首屏顺序：岗位摘要 → 资格结论与冲突提示 → 正文/在招/入口/条件四项证据 → 下一步操作 → 次要模型分数。
各证据展示“已核验 / 待核验 / 不可用”及原因；已截止与无法确认当前招聘不能共用一个“失效”标签。
后续 Tabs 分为“岗位原文”“评价依据”“来源与核验历史”；显示原始来源、核验时间、附件页码或表格行证据（存在时）。
摘要必须来自已有字段与证据，不用模型编造缺失内容；来源冲突保留并列解释，高分不得将未知或不满足改为推荐。
已核验入口显示“前往投递”；未知入口显示“查看入口（待核验）”；沟通入口显示“打开沟通入口”，不能记作已可投递。
手动记录投递继续允许；确认写入成功后更新状态并提示。证据核验的活动/预算限制沿用已批准服务契约，并解释不可用原因。
底部操作可固定，但必须为内容预留空间，不遮挡焦点、错误或最后一行；键盘能到达全部操作。

## 7. 招聘来源：展开需要处理的来源

页头说明“来源目录共享，启用配置和登录按当前版本保存”；显示实际可采来源、近期核验与运行问题摘要。
列表支持来源名称搜索、类别、启用状态、健康状态筛选；每行呈现类型、实际能力、上次检查、关键问题及进入详情操作。
详情用 Sheet 或 Collapsible 按需展开配置、站点、公众号文章/账号、微博账号、服务价格与登录操作；站点可搜索、分页。
页面统一查询根任务活动并向子组件传递；站点不再各自请求同一活动。来源详情查询独立缓存键必须包含所属版本与来源。
详情关闭或保存后保留搜索、筛选和页码；未匹配来源的空状态提供清除筛选，未启用来源的空状态提供启用入口。
保留真实探针状态；目录标记 ready 不直接显示“所有岗位可用”，正文和入口能力需要近期核验时间支持。
Boss、公众号、微博专用会话显示所属目标与登录状态；平台限制、人工验证和暂停有清晰提示，既有风险规则不因界面变化放宽。
一个来源失败时标记该来源并提供日志入口；其他来源的结果继续可见，不使用遮盖整页的错误弹窗。

## 8. 其余六页与回收站

| 页面 | 主要组织与操作 |
| --- | --- |
| 投递进度 | 状态分组与当前页计数，岗位/企业/更新时间清晰；不把分页计数冒充全库总数；详情编辑成功提示 |
| 简历管理 | 名称、更新时间、提取状态、主要资料摘要；导入/校正分别成步骤；原始技术 ID 隐藏到详情 |
| 求职目标 | 名称、绑定简历副本、方向/地区、启用状态；新建表单分组，同名检查和字段错误紧邻输入 |
| 运行日志 | 人类可读阶段、结果、计数、耗时及错误原因；错误编号和白名单技术字段收进高级详情，筛选与导出保留 |
| 设置 | 模型与费用、数据目录、备份恢复、迁移分区；迁移/去重预览以语义计数和受影响项目表达，保留技术详情 |
| 回收站 | 名称/种类、子数据数量、回收时间、剩余时间、状态；详情展示语义摘要，恢复/删除/清空均有准确范围预览 |

回收站显示状态：未到期可恢复/永久删除；到期不展示业务正文；清理中显示进展；清理失败提供重试与日志；已永久删除不保留业务行。
“清空回收站”始终覆盖整个回收站，与当前筛选区分；确认窗列出整包删除影响，沿用预览版本与计划哈希，409 后重新预览。
部分删除成功单独提示完成数量与剩余问题；不能显示全部成功。回收站名称占用直到永久删除实际完成。
业务页不直接铺 `JSON.stringify`；诊断保留白名单 JSON 到“技术详情”展开区，不用语义摘要隐藏排障证据。
备份恢复、迁移与去重继续展示预览结果和范围；高级诊断不显示简历正文、求职关键词、凭据、网页正文或私人路径。

## 9. 组件与数据边界

新增呈现层组件优先围绕统一活动摘要、证据摘要、来源列表/详情；服务端权限、数据归属与真实状态仍为权威来源。
沿用 Sidebar、Table、Card、Badge、Tabs、Field、Sheet、Dialog、AlertDialog 与 Collapsible；使用本项目 Base UI 的 `render` 组合方式，不混用 Radix API。[Table](https://ui.shadcn.com/docs/components/base/table)、[Base UI Dialog](https://base-ui.com/react/components/dialog)
预算展示由统一读取接口/视图模型提供，区分默认配置、已保存配置与当前根任务剩余额度；删除创建目标与运行选项中的互相矛盾硬编码文案。
覆盖模式最大值不等于当次启用来源数量；摘要用实际规划值。请求、附件、重试与模型账本规则保持现有契约。
分页优先于新增复杂虚拟化；不为本次视觉需求引入大型动画库、远程资源或另一套组件库，保持本地资源与 CSP 约束。

## 10. 交互、错误与动效

保存保留草稿；校验错误紧邻字段，错误摘要可聚焦到输入；等待时按钮说明进行中的动作，防止重复提交。
表单成功后清除已解决错误；异步名称检查结果与当前输入绑定，避免旧响应阻止新名称或错误放行重复名称。
成功提示仅在服务确认后显示；错误说明失败动作、原因与下一步，并提供白名单错误编号。局部失败保留已成功结果，不回填虚假成功状态。
普通成功提示短暂展示并可被读屏感知；失败及需要处理的警告留在对应区域，直到解决或明确关闭；运行进度不反复触发读屏通知。
回收、永久删除与清空使用明确范围的确认；普通可逆编辑继续直接完成。弹窗关闭返回触发按钮，键盘焦点不移出弹窗。
交互命中区域至少 44px，图标按钮有名称；修复 Tabs 容器 32px 与触发器最小 44px 的冲突，不能以缩小触发器解决。
加载仅覆盖正在改变的区域；长任务显示阶段与取消入口。网络错误保留最后一次数据并标注更新时间，避免将旧数据当作最新成功。
动效限 150–200ms 的透明度、位移和边框反馈；避免循环粒子、滚动揭示与逐项入场。减少动效设置关闭非必要动画，任何数据不依赖动画才可见。

## 11. 响应与验收

1440/1024px 保留桌面导航；768px 起收为可打开的导航面板；375px 单列、过滤折叠、详情占满可用宽度，表格只在专用容器横向滚动。
验收覆盖上述四宽度与 Windows 100%/150%/200% 缩放，长中文名称、空数据、长错误、分页和回收站到期状态；页面无意外横向滚动。
通过标准：九页路由与版本归属保留；状态不矛盾；岗位详情首屏可判断证据和下一步；来源大量配置仍可筛选、按需展开，活动查询不随站点数增长。
通过标准：所有业务 JSON 转成可读摘要；实际预算来源一致；每次服务确认的写入/恢复/删除有提示，失败无成功提示；未知与不满足正确区分。
状态场景至少包括开始、暂停、恢复、取消后重开、部分成功、预算耗尽、登录失效、人工验证、保存失败及删除部分失败。
来源页以 50 个来源及大量站点的合成配置验收：初始页只加载摘要，分页可达全部来源，详情请求按需发生，无每站点活动请求。
岗位详情在 1440px 与 375px 下优先展示结论和缺失证据；没有正文、没有入口、条件冲突及高分低证据均能识别。
预算验收比较新建目标、运行选项、活动卡和设置的实际数据；不允许保留 12/120 与 24/400 等旧新默认值矛盾。
回收站验收检查筛选后清空仍显示全范围、到期不可恢复、409 必须重新预览、部分删除不释放未删除名称。
验证键盘全流程、焦点可见且无遮挡、文本对比度、减少动效及读屏名称；回收/到期/部分清理失败使用合成数据，避免真实破坏性删除。
执行时再完成组件/状态验证、生产构建和新 EXE 九页截图检查；旧截图仅为问题线索，不能作为本设计已完成的证据。
实施计划与验收结果独立记录；本文件通过审阅后再进入本次 UI 实施，原已批准九项计划与用户简历来源测试继续推进。
