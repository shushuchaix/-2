# 启动岗位更新补充设计

用户于 2026-10-13 确认短方案并明确要求实施。本设计补充已批准的工作台、版本隔离与来源扩容设计。

## 行为

- 每次打开应用，为选中的启用目标自动更新一次。没有选择且只有一个启用目标时自动选中；多个目标未选择时提示选择。全部目标是只读汇总。
- 自动更新使用本地规则评价。招聘来源页新增“手动更新岗位”；工作台保留原更新入口和模型选项。
- 自动与手动共享现有采集活动、预算账本、版本内去重、任务进度和错误提示。已有执行任务接续显示；可自动继续的暂停活动沿用原根和额度。
- 主动暂停、登录限制、重新规划要求、取消及额度耗尽不能自动绕过。失败保留已有岗位，允许用户通过既有入口处理原因。
- 本次启动的目标切换后不会为另一个目标再次自动启动；迟到结果不能显示到新目标中。界面导航、React effect 重放及重新挂载不重复创建任务。

## 实现边界

应用级 JobUpdateProvider 保存一次启动的承诺，调用既有 `/runs` 或 `/collections/:id/resume`。CollectionProvider 提供实际进度，工作台订阅同一个运行事件流。启动续采显式携带 `mode=rules` 与 `automatic=true`；服务在规划结束后的写锁内再次检查主动暂停。

来源页“刷新来源”继续读取目录和探针状态。“手动更新岗位”实际执行采集，两项操作使用不同标签。

自测使用合成隔离工作区。常规界面矩阵显式关闭自动启动；另一个原生场景打开真实启动行为，检验自动执行、导航不重复、手动执行、再次打开、归属及零模型消耗。

## 验收

覆盖单目标、多目标、停用、简历副本缺失、全部目标、重复导航、StrictMode、重新挂载、切换目标、已有活动、主动暂停、登录限制、断开请求、错误反馈、手动重试及完成计数。后端验证自动标志输入、规则模式和规划期间暂停竞态。
