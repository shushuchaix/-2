# Boss 手机确认后停在扫描成功：传输补修

日期：2026-10-15（Asia/Hong_Kong）。沿用已批准的每版本独立登录、受控只读采集与隐私边界。

## 证据与原因

用户手机已经确认，电脑仍停在“扫描成功 / 请在 App 端确认登录”。匿名公开缓存的官方登录 SDK 对扫码、二次扫码及确认等待设置 100000ms 超时；软件代理此前在 45000ms 无传输后主动关闭连接。合成 CONNECT 流程稳定复现这个期限冲突。

这是已证实的软件兼容问题。本轮没有读取真实认证请求或当前页面正文，因此不能将截图中那一次停住的全部原因都归于这个冲突。REA 与静态代码只作参考，不替代实测。

公开 SDK SHA256：91f7f1a795eec55b42bf5f298d9fba4458da2354d9aebf26a04e85cd6b932250。

## 修复方法

1. 仅手动 Boss 独立窗口的连接建立后空闲期限改为 120 秒，覆盖官方 100 秒等待；TCP 连接建立、自动采集和其他平台保持 45 秒。
2. 新增扫码创建、扫码等待、手机确认等待、最终登录提交的阶段日志。只记录阶段、耗时、HTTP 状态、请求数和字节数；不保存二维码 ID、指纹、Cookie、账号或响应正文。
3. 连接失败、被拦跳转、人工请求/DNS/字节额度耗尽均留下明确原因。额度耗尽在窗口标题提示；不自动增加额度或重新发送。
4. 保留当前版本会话、立即取消、公开 IP 校验、60 次人工请求与 20MiB 累计边界。没有复制官方刷新、重发或挑战处理链。
5. HTTP 200 只表示该请求完成，不能据此显示登录成功或解除旧风险。
