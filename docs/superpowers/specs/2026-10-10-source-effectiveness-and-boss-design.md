# 招聘扩源实效改进与 Boss 接入补充设计

日期：2026-10-10。状态：用户已通过补充设计，进入实施计划；上一轮已批准的采集流程缺陷修复独立交付。

## 1. 目标与已确认约束

利用新接入的 Agent-Reach、数据质量审计、提示词治理及 REA MCP，继续完成个人消防、机场求职工作台的招聘扩源与证据核验。主要收益是更多取得完整正文和可核实投递入口的唯一岗位，而非单纯增加目录数量。

沿用 `2026-10-09-source-expansion-and-evidence-design.md`：所有个人业务数据按目标版本隔离，同一根活动累计网络/详情/附件/模型预算不重置；DeepSeek v4.1 模型费用最多10元；资格缺证据保留未知，AI高分不能覆盖不符或缺证据；全版本去重逐版本处理；回收与永久删除覆盖子集。

用户已明确选择：**每个目标版本使用独立 Boss 窗口和登录材料，首次自行登录。** 不把已有用户级全局 Boss 窗口、加密授权文件或浏览器上下文作为产品的共享会话。

真实招聘市场可能没有符合全部个人条件的岗位，不能以保证推荐数量作为验收。验收应证明采集、字段归属、当前开放、投递入口与资格各自正确，并如实报告缺口。

## 2. 当前证据与缺口

- 工具专项回归117通过；完整上游2204通过、4失败、2跳过，4项失败在未补丁Windows基线亦复现。不能称完整上游全绿。

- Smart Explore的两个`.mjs`结构读取本轮返回无法解析，源码核查回退常规工具。

### 上轮公开试点

### 本轮已复现的原流程缺陷

1. 无截止日期的长期招聘，需要投递可用才判开放，自动投递验证却要求先判开放，形成环路。
2. 详情明确返回不可重试，活动仍入正文重试队列。
3. 详情补抓成功沿用旧失败状态，正文观察未写入、队列未完成。
4. 正文队列先截取10项，再检查到期条件，导致后续可执行项饥饿。

这些修复保持原有证据门槛，已有4项完整活动回归分别观察RED→GREEN。限定范围审阅又复现了正文截止日期尚未提取就请求投递页、空正文补抓静默清除队列两项边界；相应断言RED→GREEN，最终5项活动回归通过。完整测试与成品验证另行记录。

## 3. 接入方式比较与选择

| 方式                                            | 优点                                                          | 限制                                                                                  | 选择         |
| ----------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------------ |
| 产品内受控Boss通道，复用已核实网页POST/Ajax契约 | 可复用现有逐版本会话、发送前预约、取消与回收；便携EXE独立使用 | 必须实测Electron内登录、Ajax钩子与平台响应，不能外推外部Chrome结果                    | **推荐**     |
| 外部SDK与每版本独立Chrome/CDP broker            | 开发期接近已验证工具行为                                      | SDK使用外部contexts[0]，缺预算/取消回调且有上下文销毁后重发；需要额外控制层和发行依赖 | 保留诊断用途 |
| 外部工具读取后人工导入                          | 可立即参考一页真实结果                                        | 无自动分页、持续采集与产品内请求计量                                                  | 作为人工补充 |

Agent-Reach和已安装SDK用于核对接口、对照样本及诊断。正式产品采用固定、受控的只读采集接口，不把个人工具绝对路径写入EXE。

## 4. Boss来源与受控浏览器

### 4.1 数据流

```mermaid
flowchart LR
  P[目标版本与根活动] --> S[Boss逐页来源]
  S --> B[该版本专用浏览器]
  B --> G[持久请求许可与预算]
  G --> W[固定搜索 / JD只读接口]
  W --> N[白名单字段与正文证据]
  N --> C[原子入库与游标提交]
  C --> V[时效 / 投递 / 资格核验]
  V --> J[本版本岗位库]
```

### 4.2 页面请求契约

- 搜索：精确限制`https://www.zhipin.com/wapi/zpgeek/search/joblist.json`，POST表单。参数仅query、city、page、pageSize、scene及明确校验的筛选字段；分页与页大小有上限。
- JD：精确限制`https://www.zhipin.com/wapi/zpgeek/job/card.json`，GET，参数仅本次已取得的`securityId/lid`；不得回退httpx或其他后端。
- 使用专用远程窗口页面主执行环境中的既有`window.$.ajax`，由页面自身`beforeSend`处理认证。调用前验证窗口所有者、URL、活动epoch和lease。
- 页面缺Ajax钩子或接口结构变化时返回明确不可用，禁止自己生成或复制认证Token。
- 业务响应只接受code 0和已核对结构；HTTP200、授权窗口存在、Cookie存在均不能代替成功。
- 只读取公开岗位/公司/薪资/地点/条件正文。打招呼、发送简历、投递、联系、聊天、收藏等接口全部拒绝。

现有`browser.read`只有导航与DOM读取，现有自动页面策略只允许GET/HEAD。本次新增固定类型的`boss.search`与`boss.detail`JSON读取操作；仅搜索精确路径允许自动POST，并校验表单参数、响应大小和所属操作。其余路径继续使用原方法限制，不增加通用页面执行或任意请求接口。

### 4.3 归属、分页与字段

Boss provider复用现有`collectPage`与`fetchDetail`，一页一个原子提交。游标保存查询、页号、解析版本和已见公开岗位身份；暂停、重启、继续共享原根预算。

保留可核对的公开岗位URL/稳定ID。`securityId/lid`仅用于当前读取调用，不写入日志、业务备份或长期游标；重启补抓需要重新取得调用引用，该请求继续计费。不能把临时安全标识认定为稳定岗位权威ID。

按来源白名单映射标题、公司、城市、薪资、学历、经验、岗位类型及正文；未声明的证书、日期、学历条件保持未知。保存来源字段/正文位置和核验时间。岗位原文含多个岗位时继续使用同岗位段落与附件行归属校验。

### 4.4 平台开放与入口证据

新增独立的`platformEvidence`，记录岗位身份、平台声明的招聘状态、入口种类及观测时间。只有原站实测确认招聘中枚举/文案语义、列表与详情同一岗位ID、没有字段冲突且观察不超过72小时，才能标记平台招聘状态已核验；业务code0、详情存在、静态按钮存在均不能代替此证据。过期截止、关闭、历史及冲突优先阻止推荐。

入口区分`apply`与`communication`。“立即沟通”只证明沟通入口存在，`applicationStatus`仍为unknown。明确同岗位、已登录且未禁用的“投递/申请”入口可形成独立平台入口证据；`formVerified`保持false，不点击该入口，也不调用提交或联系接口。展示时明确来源为平台声明/入口观察。

本轮先保存并展示这些观察，现有已核实推荐仍要求可靠开放、投递及资格证据。未能在原站核实字段语义，或只有沟通入口时，保持unknown/needs-review。验收允许Boss正文读取成功但已核实推荐为0，不为提高推荐数量推定仍在招或可投递。

## 5. 会话、请求预算、取消与风控

### 5.1 独立会话

扩展现有session manager的平台白名单与路由策略，Boss会话继续绑定packageId、targetRevisionId及会话实例。远程窗口无Node、无产品bridge或preload。首次登录由用户完成；人工登录流量与自动采集分别标记。

每个版本长期复用自己的session partition。清除登录材料、版本归档/删除、备份恢复和72小时清理沿用现有生命周期保护，撤销旧sessionRef及所有活动读取引用。恢复备份不恢复有效认证。

### 5.2 调用前预约与取消

所有自动请求、跳转、页面资源、失败及重发均通过原受控出站通道，在发送之前持久预约。正文和响应字节受上限保护；JD另消耗详情额度。可信已知消耗结算，未知部分保留预约上界。

禁止SDK内部未经许可的重发。页面上下文销毁属于一次失败，不自动再次evaluate同一请求。根活动仍支持暂停、取消及重启人工继续。

AJAX请求保存当前操作专属abort句柄。取消时先停止发放许可、abort未完成请求、终止读取并等待窗口/子进程排空；迟到结果由原epoch/lease拒绝。不得仅终止控制进程就声称浏览器请求已取消。

### 5.3 风控停止闩锁

账户/环境风险立即关闭本版本Boss会话的全部自动列表与JD任务，持久记录风险阻塞。不会自动刷新、重试、重新登录、换窗口或换后端。

普通认证过期与风控分开，code37按经核对的响应语义分类；无法识别时保守阻塞。只有用户处理专用窗口后，明确点击解除并重新核验才恢复；普通“继续采集”不解除风险闩锁。其他来源可以按原活动预算继续。

## 6. 现有来源的实效改进

1. 优先补NCSS正文与明确报名链接，提取截止语义而非发布日期；只有实际表单/授权投递证据才判入口可用。
2. 保存可复现的公开详情样本，修正贵州等官方公告正文选择器；动态页面采用现有受控浏览器与匿名增强通道。受限或挑战页面保留状态。
3. 公告拆出的岗位也进入正文、投递、时效核验流程，不能只完成抽取即跳过验证。
4. 来源发现可使用Agent-Reach的公开搜索、RSS、公开招聘讨论等能力，优先回到机构官网核对。第三方搜索/网页中继仅作线索或补充证据，不证明当前在招；不转发私人URL、签名参数、画像或凭据。
5. 公众号/微博继续使用现有独立窗口、可信账号与公开链接队列，补足真实登录后的列表/全文/附件验证。受限渠道不标ready；其他未登录平台先保留候选能力。

范围保持消防、机场及符合目标条件的企业岗位。没有验证的渠道不因为安装工具成功而自动启用。

## 7. 岗位质量契约

建立项目自己的质量投影，使用匿名字段与计数分析。关键维度独立呈现：唯一线索、正文完整、当前开放、投递可用、资格符合/未知/不符、历史/过期、疑似重复及已核实推荐。

分母必须明示。历史与待核验可以重叠；不得将重叠计数相加。URL/岗位ID高基数属于正常身份，不视为数据无效。缺证书、城市、日期和经验不能统计填补为符合。

每100请求新增有效唯一岗位只用已知自动请求作明示分母，未知上界另列。样本不足的误合并率、召回率及准确率显示未测量；不采用技能固定DQS分数冒充实测。

每个失败详情保留安全错误码、尝试次数、可重试性和服务器等待时间。同一详情连续自动补抓最多3次，达到上限转为需人工处理，成功后清零；不可重试错误直接保留线索及错误提示。服务器等待不可手动绕过；到期队列先筛可执行项再限量。原因修复后允许显式重检，该次仍消耗原根预算，而非永久丢弃岗位。

## 8. 提示词治理与黄金集

建立最小文件注册表，登记匹配与公告抽取的prompt、schema、parser、模型身份、状态和可回退版本。缓存键覆盖上述版本及正文指纹；改提示词或模型即失效相关旧抽取缓存。

至少24个合成通用黄金样例，覆盖跨岗位字段串用、证书必需/优先/未知、账号城市/工作城市、发布/截止日期、投递/登录/验证码、招聘/求职/培训、截断正文、重复/漏ID/虚构引文和正文恶意指令。

离线回放证明校验器、资格与推荐门槛；真实模型测量另列。结构合法100%、危险误推荐0、关键字段/分类至少95%，且合法正例必须能产出岗位。模型实验与采集共享指定验收根活动的10元累计上限，余额不足停止，不另开额度凑样本。

## 9. 界面、日志与验收

招聘来源增加Boss能力状态、独立登录、正文探针和风控阻塞说明；按当前版本显示，不引入通用终端或任意脚本入口。风险解除、会话清理、暂停继续与成功保存均有明确提示。

工作台显示质量转化与失败原因，岗位详情显示证据缺口。补齐expired/invalid细分标签，避免历史与投递失效都显示笼统待核验。

日志仅记录活动/来源/阶段、方法、路由种类、计数、状态、错误码与预算；不保存Cookie/Token、请求参数值、完整正文、简历或私人路径。REA诊断只保留所需白名单元数据。

### 验收顺序

1. 四项原流程缺陷回归、不可重试/服务器等待、挑战正文与公平队列均通过。
2. Boss合成协议测试：POST表单、页面主环境、所有权、发送前预约、每次实际发送、取消abort、上下文销毁不重发、风控停止所有本会话单元。
3. 双版本真实专用窗口证明会话独立、远程无bridge、清理及迟到写入拒绝。
4. 用户首次登录后，在同一活动小样本搜索、至少一份JD、后续页与停止/继续；若平台受限保存原因，不宣称线上成功。
5. NCSS与官方公告小样本补抓，分别报告正文、投递、开放及资格转化。实际个人符合数量如实呈现。
6. 黄金集离线/真实模型结果分开；完整离线、类型、成品包和EXE三DPI验证；最新同提交CI后更新原PR，不自行合并。

本补充设计通过后编写实施计划，执行方式沿用当前会话。原方案的四项缺陷修复单独交付，新增Boss及质量治理结构以本文件审阅结果为准。
