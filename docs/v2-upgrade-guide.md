# Job Radar v2 升级指南

## 1. 确认数据位置

Web / CLI 默认数据目录为项目下 `data/`；设置 `RJR_DATA_DIR` 可以覆盖。桌面通过「文件 → 打开数据目录」查看实际位置。三入口只有指向同一数据目录时才共享记录。

先停止使用该数据目录的旧版进程，将整个数据目录和个人配置另存一份。配置或系统加密文件可能含凭据，不能上传到公开仓库。此次开发在隔离工作树进行，没有修改原 `E:/简历脚本` 的业务数据。

## 2. 首次启动与迁移

安装锁定依赖，启动 v2：

```powershell
npm ci --ignore-scripts
npm start
```

启动检查 v1 `job-index.json` 与 `runs/*.json`。程序先把实际迁移输入复制到 `backups/v1-<hash>/` 并写 SHA-256 清单，再创建 `workspace.v2.json` 与 `runs-v2/`。旧文件保持原样。

- 同一批输入重复启动不会重复导入。
- 旧岗位、JD、来源日期和人工状态/备注分别保留；旧评分标为 legacy，不能当作新目标的评价。
- 旧记录身份不明确时保留候选关联和迁移冲突，不销毁融合；人工记录的旧 ID 保留可追溯关系。
- 投递页「待确认旧记录」可查看候选岗位、编辑原状态和备注。它们作为独立人工记录导出，不自动赋予候选岗位投递状态；按目标或岗位事实筛选导出时不包括尚未确定归属的旧记录。
- 旧检索输入在首次迁移后发生变化，会要求显式处理，防止把新旧工作区混写。
- 损坏索引、未知新版 schema 或无法校验的工作区会明确失败。不要通过删除文件让错误看似消失。

本次原数据预检：163 条索引岗位、20 个历史文件，预期导入 244 个岗位、20 次运行、163 份人工记录；11 项身份关联冲突保留，跳过 0。真实迁移尚未在原目录执行。已把 21 个迁移输入及 SHA-256 清单备份到当前工作树 `.cache/original-v1-backup-vlygea/`；该副本包含个人资料，未纳入 Git 或发布包。详见 [预检摘要](reports/2026-10-05-v1-preflight.json)。

## 3. 开始使用新工作台

1. 导入或粘贴简历，核对提取结果后保存画像版本。
2. 建立目标，明确城市模式、学历语义、届别、岗位类型和来源预算。
3. 更新来源并查看每源覆盖、请求预算、任务状态；部分失败的已取得岗位仍可用。
4. 在岗位详情核对来源原文和资格证据。缺失发布日期显示未提供；首次发现不是发布时间。
5. 在投递页保存状态、备注、简历版本和日期。清空备注也是一次有效修改。
6. 修改简历后创建新版本；选择新目标对保存岗位重新评分，人工记录保留。

无模型密钥时可完整使用规则模式。Web 本次更新的临时密钥只存在进程内存；桌面设置页通过系统加密保存。业务备份不携带这些密钥。

## 4. 备份与恢复

设置页「下载工作区备份」包含岗位、画像、目标、观察、评分、人工记录、运行元数据与运行快照。恢复前先校验 schema、引用和所有哈希，并先备份当前工作区。正在运行任务时先完成或取消任务再恢复。损坏备份会拒绝写入，现有备注等记录保持原样。

旧运行也纳入业务备份。备份中未完成的任务恢复后标记为中断并清除旧进程所有者，已采集事实保留在岗位库；请重新更新来源，不会自动恢复执行。

添加自定义站点时会同时验证内置目录及字段，冲突以400拒绝且不保存。若早期v2版本已经写入有问题的自定义项，可调用 `DELETE /api/v2/sources/sites/<siteId>` 删除该自定义项，内置站点仍保留。来源暂时失败会退避5分钟，已验证能力在退避到期后可重试；设置页保留上次成功与本次尝试时间。

系统层面完整备份还应包含：

- `workspace.v2.json`、`workspace.v2.previous.json`（若有）；
- `runs-v2/`、`backups/`、旧 `job-index.json` 与 `runs/`；
- 自行管理的 `config.json`、`.env`、`credentials.v2.json`、会话及配额文件。

系统加密文件通常绑定当前系统账户，跨电脑移动后可能需要重新设置密钥；业务备份仍可移植。更新期间先停服务再复制完整目录，避免跨文件快照不同步。

## 5. 回退

v1 只认识旧索引和 `runs/`，无法读取 v2 中新增的投递记录与版本。回退使用升级前单独备份的数据目录及旧版代码；不要让 v1 和 v2 同时写同一个目录。回退会丢失备份时间之后仅写入 v2 的修改，应先导出岗位与人工记录供人工核对。

v2 在原目录保留旧文件，是可追溯迁移输入；这些文件不是持续同步的 v1 副本。

## 6. 招聘渠道和部署限制

有效自动来源见 [实际验收报告](reports/2026-10-05-source-readiness.md)，候选目录不代表接通。微信公众号、微博和抖音在本版提供搜索发现与正文导入，没有已验证的直接自动采集；详见 [研究记录](reports/2026-10-05-social-sources.md)。

共享部署只有一个工作区，口令验证不提供用户隔离。给他人试用请使用另一个数据目录和合成资料。Docker 配置检查通过，但本机没有可用 Docker 引擎，未执行容器构建与启动。模型实际质量和调用费用没有带真实密钥验收。
