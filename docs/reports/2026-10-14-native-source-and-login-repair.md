## Boss 空白窗口的原因与修复

实际日志中两次手动窗口均发送 1 次请求、接收 0 字节。系统 DNS 的 Boss 域名结果落在 Fake-IP 段；旧手动窗口没有使用已有公共 DNS 回退。匿名官网入口随后取得 HTTP 200，其登录 SPA 还依赖两个此前被策略拦截的官方 CDN。

修复沿用每版本独立会话。页面及 DNS 请求共用每窗口 60 次、20 MiB 上限；加载等待最长 45 秒。失败有诊断编号及安全错误码，关闭窗口或版本时保留取消结果。CDN 许可限定静态 GET/HEAD、资源类型和已观察到的路径，拒绝查询私参、编码目录路径及任意新主机。

REA 对两个匿名取得的官方脚本作了静态分析：459,199 字节，2 个 JavaScript 文件，解析失败 0；脚本未执行。原始证据只保存在忽略的诊断目录。此结果用于核对依赖，不作为二维码或登录成功证据。

界面补充了实际入口说明：**招聘来源 → 搜索 Boss → 查看来源配置 → Boss直聘独立登录 → 打开独立采集窗口**。打开 Boss 页面后，由用户选择网页的登录/注册并扫码，再返回软件核验；关闭窗口不会自动核验。
